# Worker 角色与预热池

这份参考文档定义主机侧的 worker 部署接口，适用于需要并行运行多个 DSH 会话的集成。worker 角色声明会话所需的最小能力。预热池保留空闲 worker，避免把项目目录或用户目录写成永久授权。

## 角色

初始角色注册表包含三个名称。

| 角色 | 能力 | 常见用途 |
| --- | --- | --- |
| `local-readonly` | 读取工作区文件并运行只读命令 | 检查、发现和静态检查 |
| `local-edit` | 读取和写入工作区文件并运行命令 | 本地修改和构建 |
| `remote-runner` | 读取工作区文件、运行命令、使用 SSH 和网络 | 远程检查和远程执行 |

角色名称是标识符。部署可以增加角色，但必须同时声明能力集合和生命周期限制。调用方指定角色后，主机返回该角色或明确的能力错误，不得静默扩大角色权限。

## 预热池接口

主机为每个角色维护一个预热池。池配置声明预热数量、最大租借数、空闲超时和回收策略。预热池提供三个操作。

```text
acquire(role, request) -> lease
lease.release(outcome)
pool.close()
```

`request` 携带 `read_paths`、`write_paths`、`ssh_hosts`、`network` 和需要运行的命令等资源意图。预热池在启动 worker 前检查资源意图是否符合角色。worker 启动后只执行一次轻量能力探针。路径、命令、SSH 主机或网络请求被拒绝时返回权限错误，不把它转换成停滞会话。

租约负责清理临时工作区挂载、子进程和凭据引用。探针失败的 worker 会被销毁，不会回收到预热池。超过空闲超时的 worker 也会被销毁，只有在预热数量策略要求时才创建替代实例。

## 会话部署

会话创建接受可选的 `workerRole`。未指定时，主机根据资源意图选择满足要求的最小角色。MCP 或其他传输适配器只转发角色和资源意图，不创建或管理预热池。

会话释放会在子进程和流结束后归还租约。失败会话同样必须归还租约。会话结果记录所选角色和探针结果，让调用方区分权限失败与执行失败。

## 配置示例

```yaml
workerPools:
  local-readonly:
    warmSize: 2
    maxLeased: 8
    idleTimeoutMs: 300000
  local-edit:
    warmSize: 1
    maxLeased: 4
    idleTimeoutMs: 300000
  remote-runner:
    warmSize: 1
    maxLeased: 2
    idleTimeoutMs: 600000
```

配置只在进程内生效，不写入永久项目路径、用户目录、密钥或操作系统 ACL。资源意图按会话提供，租约释放后清除。

## 失败与归属

调用方负责选择角色。主机负责能力检查、预热池准入和清理。角色不匹配、能力不可用或探针失败时返回结构化权限错误。配额和限流错误可以遵循部署的重试策略。权限错误不得作为模型错误或 worker 错误重试。
